\begin{abstract}
Autonomous large language model (LLM) agents write, run, and revise code
inside their reasoning loop, which puts the sandbox on the hot path of every
task. Roll-your-own Docker is quick but usually deployed without a
read-only root, capability drops, process caps, or egress control; hosted
sandbox services are hardened but move the operator's code and data to a
third party; research virtual machine monitors isolate well but are built
for a boot-once serverless model. Boxed is an open-source substrate for
agentic code execution: a self-hosted Go control plane, a
\BoxedAgentBinSize{} Rust in-sandbox agent that streams \texttt{stdout},
\texttt{stderr}, and files over JSON-RPC~2.0, and a driver interface whose
four lifecycle methods admit backends beyond the Docker driver that exists
today. Measured against the Docker Engine API on the same host, image, and
command, the control plane and agent cost \BoxedOverheadPct{} of a raw
Docker lifecycle on a laptop and on an idle server alike, and the hardened
configuration is faster than stock Docker defaults, because dropping the
network costs less than setting up the bridge. Swapping the OCI
runtime under the unchanged driver gives \RuncBoxedMedian{} per lifecycle
with \texttt{runc}, \RunscBoxedMedian{} with gVisor, and
\KataBoxedMedian{} with a Kata microVM, the substrate cost near constant
across the three; a twelve-vector escape probe scored by post-conditions
read from the host denies all twelve under \texttt{runc} and gVisor and
eleven under Kata, whose guest kernel lacks the host policy that had been
stopping a \texttt{ptrace} attach on the in-sandbox agent; a one-line
change to the agent restores twelve. A driver setting that gives the
microVM an internal, inter-container-isolated network and no CPU quota
cuts the Kata lifecycle to \KataAwareBoxedMedian{} with all twelve still
denied. On the same host, the OpenHands agent-server sandbox in its SDK's
default configuration takes \OHMedian{} per lifecycle and stops
\OHDenied{} of the twelve vectors, leaving the cloud metadata endpoint and
the instance's service-account token reachable. Single-host throughput is
bound by the Docker daemon: four times the cores gives \ScaleRatioMax{}
the sandboxes per second. Boxed, the harness, and every raw trace are
MIT-licensed.
\end{abstract}

\section{Introduction}\label{sec:intro}

Autonomous code-generating agents arrived in force between 2024 and 2026,
from Yang \emph{et al.}'s SWE-agent~\cite{sweagent} and the AutoGPT-style
harnesses to products such as Cursor, Devin, and Claude Code, and they
changed what ``running untrusted code'' means in practice. Executable code
has been argued to be a better action space for an agent than text or
JSON~\cite{codeact}. An agent built that way emits dozens of short programs
per task: it writes a snippet, runs it, reads \texttt{stdout}, reads back a
file it produced, and tries again. The sandbox sits inside that loop, and its
latency is paid on every iteration.

An operator who wants that loop hosted has three options today, and each
gives something up.

\textbf{Roll-your-own Docker} is the common choice: quick to set up and
routinely shipped without seccomp profiles, egress filters, a read-only
root filesystem, or process and memory caps, which leaves the host one
\texttt{rm -rf /} away from compromise~\cite{runc-cve}; measurement
studies report the same pattern at scale~\cite{container-measure}, and
cgroup-based resource isolation can itself be
evaded~\cite{houdini-cgroups}. \textbf{Hosted sandbox services}
(E2B~\cite{e2b}, Modal Sandbox~\cite{modal}, Cloudflare
Sandbox~\cite{cfsandbox}) ship hardened isolation, and in exchange every
byte of generated code, output, and artifact leaves the operator's
infrastructure for a third party, which some deployment rules do not allow.
\textbf{Research VMMs} such as Firecracker~\cite{firecracker} have the
right primitives but are built for AWS Lambda's boot-once model and have no
in-guest agent to stream artifacts back to the caller.

What agent workloads need is a \emph{substrate}: an isolation backend chosen
at deployment time, an agent inside the sandbox that streams standard output
and on-disk artifacts as they appear, and a deployment the operator runs,
with the control plane and the workload data under their control.

\subsection{Problem Statement}

An autonomous coding agent runs untrusted, machine-generated code many times
in a single task, and three things have to hold at once. The isolation
boundary has to contain code nobody reviewed. Per-execution latency has to
stay low enough that the sandbox does not dominate the agent's loop. And the
operator has to keep control of the keys and the data, because agent
workloads carry proprietary source and customer records into the sandbox as
a matter of course.

No existing substrate satisfies all three. Hosted services meet the first
two, but they put a third party inside the trust boundary and give the
operator no say over the isolation backend. Self-hosted container runtimes
leave the operator in charge but tie the control plane to one isolation
technology, so a stronger boundary later means rewriting the orchestration
layer. Boxed targets that gap: keep the control plane, the keys, and the data
with the operator, and make the isolation backend a deployment-time choice.

Two questions follow, and Section~\ref{sec:eval} answers them by
measurement. What do the control plane and agent cost over calling Docker
directly on the same host, image, and command? And once the Docker driver
applies the hardening that roll-your-own deployments skip, which of a
standard set of container-escape vectors does it stop, judged by the state
left after each attempt and not by strings in the attempt's output?

\subsection{Objectives}

\begin{itemize}
\item An isolation interface narrow enough that container runtimes,
microVMs, and Wasm sandboxes can be interchanged behind it without changing
the control plane.
\item Incremental delivery of output and of files produced during
execution, as events on one channel.
\item Self-hosted deployment with no Boxed-operated service in the data
path.
\item Measured cost and limits against a raw-Docker baseline, failures
included.
\end{itemize}

\subsection{Contributions}

\begin{itemize}
\item A Go driver interface whose four lifecycle methods
(\texttt{Create}, \texttt{Start}, \texttt{Stop}, \texttt{Connect}) are the
contract a backend has to satisfy, so that the isolation backend becomes a
deployment-time setting. The release implements one backend, Docker. No
microVM or Wasm backend exists yet, and this paper claims only what the
Docker driver does.
\item A Rust in-sandbox agent that streams \texttt{stdout} and \texttt{stderr}
chunks as discrete JSON-RPC events instead of buffering until process exit,
mirrors files written under a watched directory back to the caller as
artifact events, and reports the child's real exit status.
\item A self-hosted control plane authenticated by an operator-configured
API key. It authenticates one instance and does not manage credentials or
tenants.
\item A released benchmark harness and campaign: lifecycle latency against
raw Docker through the Engine API on the same host; throughput under
concurrency with repeated sweeps and confidence intervals; idle per-sandbox
overhead; a twelve-vector escape probe scored by post-condition checks read
from the host; and an end-to-end agent trace on official HumanEval tasks
with the model, prompts, token counts, and exit codes recorded. Raw CSV and
JSONL traces ship with the source.
\item A comparison of post-condition scoring with the signature matching
that escape probes commonly use, on the same attempts: signature matching
misreports as failures exactly the vectors where enforcement kills or
silences the process.
\item The same driver, agent, and harness under three OCI runtimes on one
host (\texttt{runc}, gVisor, Kata). This measures the backend switch the
interface was designed for, exposes and closes a \texttt{ptrace} gap that
the container runtime had been masking, and shows that two hardening
settings free under \texttt{runc} cost seconds under a microVM, with the
driver setting that removes that cost.
\item The OpenHands agent-server sandbox measured with the same harness on
the same host, and a core-scaling sweep on 4, 8, and 16 vCPUs showing that
single-host throughput is bound by the daemon.
\end{itemize}

\section{Background and Related Work}\label{sec:related}

\subsection{Container-based isolation}
Linux containers, built on namespaces, cgroups, and seccomp, underpin nearly
every development sandbox. They start fast when images are warm
(\BaseDefCreateMedian{} for a stock \texttt{docker run} on our host,
Table~\ref{tab:lifecycle}), which is why they dominate workloads that
create and destroy environments often; the cost is a shared host kernel.
CVE-2019-5736~\cite{runc-cve} is the standard reminder that one bug in
\texttt{runc} turns a container into the host. Lin \emph{et
al.}~\cite{container-measure} ran 88 of 223 collected exploits inside a
default-configured container: 50 succeeded, capabilities, seccomp, and MAC
stopped more privilege escalations than namespaces and cgroups did, and 11
exploits still broke isolation, which is why the hardening in
Section~\ref{sec:hardening} starts with the capability drop. Hardened
runtimes such as gVisor~\cite{gvisor} put a userspace kernel between the
workload and the host; Young \emph{et al.}~\cite{gvisor-cost} measure its
system-call cost at 2.8$\times$ native in its fastest mode, 9$\times$ when
the call reaches the host, and 72$\times$ through the Gofer, with file opens
216$\times$ slower. Anjali \emph{et al.}~\cite{anjali-blending} compare
Linux containers, gVisor, and Firecracker on CPU, network, memory, and file
system microbenchmarks and trace the kernel code each executes; both run
substantially more kernel code than native Linux, and neither wins on every
workload. Docker can select gVisor or Kata as a runtime, which
Section~\ref{sec:runtimes} measures.

\texttt{nsjail}, \texttt{bubblewrap}, and \texttt{firejail} apply the same
namespace, seccomp, and cgroup primitives to a single process, with no image
and no daemon. For an operator who does not need Docker's image ecosystem
they are the natural comparison. Boxed uses Docker for two reasons: agent
workloads are specified as images (a Python runtime, a toolchain, a set of
packages), and the Engine API provides the exec-attach stream the in-sandbox
agent runs over. A process-sandbox backend behind the same interface is
possible but is not evaluated here.

\subsection{Lightweight virtual machines}
Agache \emph{et al.}~\cite{firecracker} showed that a stripped-down KVM
VMM can boot a guest kernel in $\sim$125\,ms with $<$5\,MiB of memory
overhead per VM, and Firecracker now powers AWS Lambda. Kata
Containers~\cite{kata}, which Section~\ref{sec:runtimes} measures as a
Docker runtime, and Manco \emph{et al.}~\cite{my-vm-is-lighter} pursue the
same hypervisor-as-isolation thesis. These systems optimize boot cost and
steady-state memory for a boot-once serverless pattern; a coding agent
creates, uses, and destroys a sandbox many times per task, so the whole
lifecycle is the cost that matters.

\subsection{Unikernels and WebAssembly}
Madhavapeddy \emph{et al.}~\cite{unikernel} compile the application together
with a library operating system into a single boot image, minimizing the
trusted computing base at the cost of application-specific compilation, which
rules out arbitrary dynamically generated binaries. WebAssembly~\cite{wasm}
and WASI~\cite{wasi} make the guest portable bytecode with capability-based
imports and the sandbox a runtime in the host process; microsecond
instantiation is what a create-heavy agent workload wants, but agents emit
unmodified Python scripts, shell commands, and native binaries that assume a
POSIX environment, which the WASI toolchain does not yet run unmodified.

\subsection{Agent-oriented sandbox platforms}
Several products now target LLM agents specifically. E2B~\cite{e2b} runs
Firecracker microVMs behind a SaaS API and reports about 150\,ms cold start;
Modal Sandbox~\cite{modal} layers gVisor over Firecracker;
Daytona~\cite{daytona} ships an AGPL, Docker-backed, self-hosted development
environment; Cloudflare Sandbox~\cite{cfsandbox} reuses V8 isolates for
about 5\,ms cold start and limits execution to JavaScript and Wasm.
OpenHands~\cite{openhands} executes every agent action in a Docker container
through a REST action-execution API inside it, the closest design to Boxed's
driver-plus-agent split, but it is an agent framework with a sandbox inside
and has no backend interface. The vendors' cold-start figures were measured
under undisclosed conditions; Table~\ref{tab:compare} repeats them as
reported. Across the category the platform fixes the isolation mechanism,
and apart from Daytona and OpenHands the platforms are hosted services.

\subsection{Evaluating LLM-generated code execution}
Chen \emph{et al.}~\cite{humaneval} made single-function code generation a
standard benchmark, and Yang \emph{et al.}~\cite{sweagent} extended it to
agents that have to \emph{run} the code they write. Our agent trace
(Section~\ref{sec:agent}) follows that regime on official HumanEval tasks
and splits wall-clock into model inference and sandbox lifecycle, which is
how much of an agent's latency a substrate can affect at all.

\section{Threat Model}\label{sec:threat}

The threat model assumes an adversary with full control over the code
submitted to a sandbox: they may craft arbitrary Linux binaries, issue any
syscall sequence, and attempt network egress to any destination. The adversary
does \emph{not} control the control plane, the driver implementation, or the
host kernel; these remain trusted.

The design aims to prevent four classes of attack.

\textbf{T1, host filesystem access.} Read or write access to the host
filesystem outside the sandbox's ephemeral root, whether through path
manipulation, symbolic links, or mount operations.

\textbf{T2, namespace escalation.} Escape from the allocated network or
process namespace into the host's network stack or process tree, or
tampering with the in-sandbox agent from a workload process that shares its
namespace.

\textbf{T3, co-tenant exfiltration.} Access to credentials, artifacts, or
data belonging to a concurrent sandbox on the same host.

\textbf{T4, resource exhaustion.} Denial of service against the host through
fork bombs, memory exhaustion, or other unbounded resource consumption.

Side channels through shared hardware are out of scope; defending against
them means per-customer hardware partitioning, an operator decision. The
escape probe in Section~\ref{sec:escape} covers T1, T2, and T4 directly and
T3 only through the network vectors, since the sandbox has no route to a
co-tenant except the network; no vector tries a cross-sandbox read through
the host.

a stateless control plane, a driver layer, and an in-sandbox agent, with
orchestration kept apart from the isolation mechanism so that one control
plane can drive Docker on a laptop and a microVM in production. Today only
the Docker driver exists.

\subsection{Driver Interface}\label{sec:driver}
The central abstraction is one Go interface. In the current source it has
twelve methods; eight are helpers for file injection, listing, health, and
naming that the SDK and control plane use. The four lifecycle methods below
are the minimum a backend has to implement, and the control plane's sandbox
path depends on nothing else:

\begin{lstlisting}[language=Go]
type Driver interface {
 Create(ctx context.Context,
 cfg SandboxConfig) (string, error)
 Start(ctx context.Context, id string) error
 Stop(ctx context.Context, id string) error
 Connect(ctx context.Context,
 id string) (io.ReadWriteCloser, error)
 // ... file, listing, and health helpers
}
\end{lstlisting}

\texttt{Create} builds a sandbox from the configuration and returns an
identifier; \texttt{Start} and \texttt{Stop} bound its lifetime;
\texttt{Connect} returns the raw byte stream the control plane uses to
talk to the in-sandbox agent (a Docker \texttt{exec} attach today; a
\texttt{vsock} connection or a host-side function for other backends).
The control plane does not know which it has. Whether four methods are
enough for a microVM backend is untested, since none has been written, and
is listed as future work.

\subsection{Control Plane}
The control plane is a stateless HTTP and WebSocket server on the Echo
framework that maps \texttt{POST /v1/sandbox} requests through the
configured driver. \texttt{create} returns as soon as the runtime reports
the sandbox process launched (for Docker, when \texttt{ContainerStart}
acknowledges), with \texttt{status: ready}; the client never polls, and the
first \texttt{exec} absorbs the wait for the agent's JSON-RPC loop. An
agent task may create dozens of sandboxes, and one round trip saved per
sandbox adds up. Authentication is a static, operator-configured API-key
header (\texttt{X-Boxed-API-Key}); Boxed does not issue, rotate, or store
keys, and this authenticates one instance without multi-tenant identity, key
management, or compliance. Generated code, execution output, and
intermediate files stay on infrastructure the operator controls.

\subsection{In-Sandbox Agent}
\texttt{boxed-agent} runs inside every sandbox: one Rust binary on
\texttt{tokio}, \texttt{serde}, and \texttt{notify}
(\BoxedAgentBinSize{} stripped; it links the C library dynamically and
needs nothing else at runtime) speaking JSON-RPC~2.0 as newline-delimited
JSON over whatever byte stream the driver supplies. On \texttt{exec} the
agent spawns the command as a child process and streams
\texttt{stdout} and \texttt{stderr} chunks back as separate RPC events as
they arrive, so a model can react to partial output or an early error before
the program finishes. When the child exits the agent reports its exit
status. At startup the agent marks itself non-dumpable
(\texttt{PR\_SET\_DUMPABLE}), for the reason Section~\ref{sec:runtimes}
gives. Alongside, an \texttt{inotify} watcher monitors the
artifact directory (\texttt{/output}). Any file written there is emitted as
an \texttt{artifact} event with the file's MIME type and base64 contents,
so an agent that asks Python to write \texttt{plot.png} gets the bytes
pushed to it, with no second round trip and no polling.

\subsection{Artifact Protocol}
Files are first-class outputs because much of what a model asks code to do
shows up as a side effect on disk and never reaches the console. The
current release streams them inline: the watcher reads the file, guesses
its MIME type, base64-encodes it, and emits it on the same channel as
\texttt{stdout} and \texttt{stderr}. A \BoxedInlineCap{} cap bounds the
memory and serialization cost; larger files are skipped with a logged
warning. The wire protocol reserves a \texttt{url} field on the artifact
event for an out-of-band path, in which the agent would \texttt{PUT} the
file to a pre-signed URL and return a reference, and that path is not
implemented. A substrate that silently drops large artifacts is a correctness hazard for
any workload that emits checkpoints or datasets. Both the protocol and the agent sit above the driver interface,
so artifact semantics do not depend on the backend.

\section{Implementation}\label{sec:impl}

The release is \BoxedGoLOC{} lines of Go in \texttt{cmd} and
\texttt{internal} (control plane, Docker driver, CLI) and \BoxedRustLOC{}
lines of Rust for the agent; the binaries are \BoxedServerBinSize{} and
\BoxedAgentBinSize{} stripped.

\subsection{Agent injection and container lifecycle}
The Docker driver bind-mounts the host's \texttt{boxed-agent} binary into the
container read-only at create time, so a stock base image
(\texttt{python:3.10-slim}) can be reused across sandboxes with no
Boxed-specific image registry to maintain. The image root filesystem is
read-only. Separate \texttt{tmpfs} mounts back \texttt{/tmp},
\texttt{/output}, and the configured working directory, so user-written data
is ephemeral and never touches the host filesystem.

The container's own PID~1 is a \texttt{tail -f /dev/null} placeholder
whose only job is to keep the namespace alive. \texttt{Connect} launches
\texttt{boxed-agent} as a Docker \texttt{exec}, and the attached stream
carries JSON-RPC. This matters for security: the agent is a child of the
container's init, so any workload process in the sandbox's PID namespace can
see it, which is why the \texttt{ptrace} vector in
Section~\ref{sec:escape} targets the agent. Under a microVM backend the
agent would be the guest init and talk over \texttt{vsock}.

\subsection{Resource and network model}\label{sec:hardening}
Every sandbox is created with a CPU quota (\texttt{NanoCPUs}), a memory
cgroup, and a \texttt{PidsLimit} of 256. The container root is read-only,
all Linux capabilities are dropped, and \texttt{no-new-privileges} is set.
Docker's default seccomp profile applies; Boxed does not yet ship its own.
The resource defaults are 1.0 core and \BoxedMemDefault{}, with ceilings of
4.0 cores and 8\,GiB. A TTL goroutine stops the sandbox when its timeout
expires.

The Docker backend always uses Docker's \texttt{none} network, so only
loopback exists. Requests that enable networking or name an allow-list are
rejected until Boxed has an enforceable per-sandbox egress policy. This
fails closed. It does not claim that Docker's default bridge would be an
adequate egress control.

\section{Evaluation}\label{sec:eval}

This section answers the two questions from Section~\ref{sec:intro}: what
the control plane and agent cost over calling Docker directly, and which
escape vectors the hardened driver stops under post-condition scoring. It
also reports throughput under concurrency, idle per-sandbox overhead, and an
end-to-end agent trace. Every number below expands from a macro that the released analysis scripts
generate from the raw traces in the repository.

\subsection{Setup}
The laptop measurements were taken on a MacBook Pro (Apple M1~Pro, 16\,GB,
macOS~26.5) with Docker Engine 29.5 (\texttt{linux/arm64}, kernel 6.8,
cgroup v2, seccomp and AppArmor on) inside a 4-vCPU, 8\,GiB colima virtual
machine on Apple's Virtualization framework. The \texttt{python:3.10-slim} image was pre-pulled. The machine ran its usual background processes (editor, browser)
throughout and was not quiesced; we report dispersion across repeated runs so
that the contention shows. Unless noted otherwise each lifecycle runs a
synthetic \texttt{print('ok')} workload, which keeps application compute out
of the substrate measurement. The Boxed control plane was
built from the tagged release with Go~1.24 and the agent with Rust~1.80.

\subsection{Lifecycle latency against raw Docker}\label{sec:lifecycle}
The substrate's cost only means something next to what Docker costs on the
same host, so three configurations ran the same
create$\rightarrow$exec$\rightarrow$destroy sequence. \emph{Raw Docker,
stock defaults} calls the Engine API with \texttt{docker run}'s default host
configuration. \emph{Raw Docker, hardened} calls the Engine API with exactly
the host configuration Boxed's driver applies (read-only root,
\texttt{CapDrop ALL}, \texttt{no-new-privileges}, PID limit, network
\texttt{none}, 1~CPU, \BoxedMemDefault, \texttt{tmpfs} mounts) and has no
control plane or agent. \emph{Boxed} goes through the HTTP API. The raw
configurations run \texttt{python3 -c "print('ok')"} through a Docker exec;
Boxed runs the same command through the in-sandbox agent. Each configuration
ran \BoxedColdRuns{} runs of \BoxedColdN{} sequential lifecycles,
interleaved so that drift on the host hits all three alike.

95\%~CI \BoxedColdMedianCI; per-run medians \BoxedColdRunMedianMin{} to
\BoxedColdRunMedianMax). The interquartile range is \BoxedColdIQR{}, and the
tail reaches \BoxedColdPNinetyFive{} at p95 and \BoxedColdPNinetyNine{} at
p99. Raw Docker with the same hardened configuration takes
\BaseHardMedian{}. Its tail is heavier than Boxed's (p95
\BaseHardPNinetyFive{}), but the tails are not a property of the
configurations: of the \BaseHardTailN{} slowest raw-hardened lifecycles,
\BaseHardTailClusterMax{} fall in a single run, and of the
\BaseDefTailN{} slowest stock lifecycles, \BaseDefTailClusterMax{} fall in
another, almost all of them in the create phase. Those are bursts of host
activity landing on whichever configuration was running, so Boxed's smaller
p95 is not an advantage of Boxed. The difference of \BoxedOverheadMedian{} (95\%~CI on the
difference of medians \BoxedOverheadCI; \BoxedOverheadPct{} of the raw cost)
is what the HTTP control plane, the agent launch over \texttt{exec} attach,
and the JSON-RPC exec path add together: \BoxedOverheadCreate{} on create,
\BoxedOverheadExec{} on the first exec, and \BoxedOverheadDestroy{} on
destroy. It buys an HTTP API that any language can call, an agent that
streams output and files as events, and a create that takes one round trip.
An operator who already drives the Engine API from Go and does not need
streaming artifacts would not pay it.

The two raw-Docker rows compare the hardening against stock defaults.
Boxed's hardened configuration is \HardeningDeltaMedian{}
\HardeningDeltaSign{} end to end than \texttt{docker run}'s defaults. The
stock configuration attaches the container to the default bridge network,
and setting up and tearing down that attachment costs more than the
\texttt{tmpfs} mounts and the capability drop do; with network
\texttt{none} that work is gone. On this host the hardening that
roll-your-own deployments skip does not cost latency.

\subsection{Throughput under concurrency}\label{sec:throughput}
Client concurrency was swept over $c \in \{1,2,4,8,16,32\}$ with
\BoxedTPPerLevel{} create$\rightarrow$destroy lifecycles per level, and the
whole sweep was repeated \BoxedTPRuns{} times. Throughput rises from
\BoxedTPatOne{}~sandboxes/s at $c{=}1$ to a plateau of \BoxedPeakRPS{}
(\BoxedPeakCI) at $c{=}\BoxedPeakConc$ and \BoxedTPatThirtyTwo{} at
$c{=}32$, with the last three levels inside one another's confidence
intervals. A single sweep at $c{=}4$ or $c{=}8$ can land anywhere in a
two-to-one band, so a curve drawn from one sweep per level, as such curves
usually are, is mostly noise. Section~\ref{sec:scaling} shows where the
plateau comes from.

\subsection{Idle per-sandbox overhead}
Each of \BoxedOverheadN{} idle sandboxes was sampled five seconds after
\texttt{create} returned. Median working set, as \texttt{docker stats}
reports it from the container cgroup, is \BoxedRSSMedian{} (p95
\BoxedRSSPNinetyFive); median CPU is \BoxedCPUMedian{}. This is cgroup
accounting inside a VM, so we take it as an order of magnitude; it fits an
agent that is a stripped Rust binary parked on one \texttt{tokio} loop.


\subsection{Escape probe with post-condition checks}\label{sec:escape}
The hardened driver was exercised with twelve attempts drawn from common
container-escape patterns: a filesystem mount, reading the host through
\texttt{/proc/1/root}, the Docker or containerd socket, loading a kernel
module, a raw socket, a new user and PID namespace, egress to an RFC1918
address and to the link-local metadata endpoint, a fork storm, a memory
bomb that touches every page, a write to the root filesystem, and
\texttt{PTRACE\_ATTACH} on the in-sandbox agent. Each attempt runs in a
fresh sandbox, and the whole suite ran \BoxedEscapeRuns{} times.

Each vector gets two verdicts on the same attempt. The \emph{signature}
verdict is the method escape probes commonly use: capture \texttt{stdout}
and \texttt{stderr} and grep for a denial string. The \emph{post-condition} verdict looks at
state after the attempt: whether a mount appeared in \texttt{/proc/mounts},
whether the written file exists, the \texttt{errno} the syscall returned,
which device and inode \texttt{/proc/1/root} resolves to, and, for the
resource vectors, the cgroup's \texttt{pids.events} and
\texttt{memory.events} counters read on the host. Table~\ref{tab:escape}
gives both verdicts and the evidence for every vector.

\input{tables/escapes}

The post-condition checks classify \BoxedEscapeDenied{} of
\BoxedEscapeTotal{} vectors as denied (\BoxedEscapePct), with
\BoxedEscapeUndenied{} undenied and \BoxedEscapeError{} harness errors, and
the verdicts were \BoxedEscapeConsistent{} across the \BoxedEscapeRuns{}
runs. The signature verdicts disagree on \BoxedEscapeSigDisagree{} of
\BoxedEscapeTotal{}, and in each case they report as undenied an attempt
the evidence shows was stopped.

The evidence column shows why. The cgroup kills the memory bomb and the
host's \texttt{oom\_kill} counter records it, but the process prints
nothing before \texttt{SIGKILL}, so a signature reads that silence as a
successful attack; the fork storm gets exactly the forks the PID limit
allows and then \texttt{EAGAIN}; \texttt{/proc/1/root} resolves to the
container's own root; with network \texttt{none} the sandbox has a
loopback interface and nothing else. The \texttt{ptrace} attach is denied
because \texttt{CapDrop ALL} removes \texttt{CAP\_SYS\_PTRACE} and the
host kernel's Yama scope of 1 limits attachment to descendants; a host
without Yama would need more, and Section~\ref{sec:runtimes} finds exactly
that host. The module-load vector calls \texttt{init\_module} directly
because the image has no \texttt{modprobe} binary, and a probe that
invoked one would measure the image. A probe scored by strings in captured
output therefore understates coverage on precisely the vectors where
enforcement kills or silences the process.

This is a behavioural probe over twelve vectors and does not prove
isolation. It does not exercise kernel vulnerabilities, it runs one image,
and it has no cross-sandbox read (T3). None of the twelve attempts escaped
the host.

\subsection{End-to-end agent trace}\label{sec:agent}
A code-generation loop drove Boxed over the first \BoxedAgentTasksPerRep{}
tasks of the official HumanEval release~\cite{humaneval} in file order,
\BoxedAgentReps{} times, for \BoxedAgentN{} task executions. For each
task the model (\texttt{\BoxedAgentModel}, default adaptive thinking,
4096 max output tokens, Anthropic Messages API, no fallback model) gets the
signature and docstring and returns the function; Boxed runs the prompt,
the completion, and the task's published \texttt{check} in a fresh
sandbox, and the exit status decides. A deliberately wrong candidate exits~1
with an \texttt{AssertionError}, which is the harness's control. Model, timestamp, prompt hash, token
counts, stop reason, raw completion, program, and captured output for every
task are in \texttt{agent\_trace.jsonl} next to each CSV.

\BoxedAgentPassCount{} of \BoxedAgentN{} task executions passed
(\BoxedAgentPass; stop reasons \BoxedAgentStopReasons). Median end-to-end
wall-clock was \BoxedAgentMedianTotal{}: the model call took
\BoxedAgentLLMMedian{} and the sandbox lifecycle \BoxedAgentSandboxMedian{}
(per-repetition medians \BoxedAgentSandboxRepRange).
Summed over all executions, model inference is \BoxedAgentLLMShare{} of
wall-clock (\BoxedAgentLLMShareRepRange{} across repetitions) and the
sandbox \BoxedAgentSandboxShare{}. Sandbox create in this loop had a median
of \BoxedAgentCreateMedian{} (\BoxedAgentCreateRepRange{} across
repetitions), against \BoxedColdCreateMedian{} in the tight lifecycle loop
of Section~\ref{sec:lifecycle}. During all three repetitions the host's
one-minute load average was between 13 and 17 on eight cores, from activity
unrelated to the experiment; the lifecycle campaign ran under lighter load,
and the recorded load is kept next to the traces. So the gap is an upper
bound on what an idle interval between creates costs, and on a quieter host
the model's share would be larger. The pass rate measures the model; for the substrate, the trace shows how
large a share of an agent iteration the sandbox takes with a current
frontier model.

\subsection{The same campaign on a native Linux host}\label{sec:linux}
To separate the cost of the virtual machine from the cost of the substrate,
the whole campaign was repeated on an idle Google Compute Engine
\texttt{n2-standard-4} (4 vCPUs, 16\,GB, Ubuntu 24.04, Docker Engine 29.7,
kernel 6.17).
Table~\ref{tab:lifecycle} (lower half) gives the lifecycle result. Boxed's median
lifecycle is \LinuxBoxedColdMedian{} against \LinuxBaseHardMedian{} for raw
hardened Docker, a substrate cost of \LinuxBoxedOverheadMedian{} (95\%~CI
\LinuxBoxedOverheadCI; \LinuxBoxedOverheadPct{} of the raw cost), and the
hardened configuration is \LinuxHardeningDeltaMedian{}
\LinuxHardeningDeltaSign{} than stock. Throughput peaks at
\LinuxBoxedPeakRPS{}~sandboxes/s (\LinuxBoxedPeakCI) at
$c{=}\LinuxBoxedPeakConc$ with \LinuxBoxedTPErrors{} errors. The escape
probe denies \LinuxBoxedEscapeDenied{} of \LinuxBoxedEscapeTotal{} vectors,
\LinuxBoxedEscapeConsistent{} across \LinuxBoxedEscapeRuns{} runs, with the
signature method disagreeing on \LinuxBoxedEscapeSigDisagree{}. The agent
trace passed \LinuxBoxedAgentPassCount{} of \LinuxBoxedAgentN{} executions
with model inference at \LinuxBoxedAgentLLMShare{} of wall-clock, and
sandbox create in the agent loop had a median of
\LinuxBoxedAgentCreateMedian{} against \LinuxBoxedColdCreateMedian{} in
the tight loop on the same host: on a quiet host the laptop's gap is gone,
as the load explanation predicted.

The substrate's share of the raw cost is \LinuxBoxedOverheadPct{} here and
\BoxedOverheadPct{} on the laptop, the hardened configuration is faster

not carry over: this Xeon is slower per lifecycle than the M1~Pro under
colima, and its dispersion is far smaller (IQR \LinuxBoxedColdIQR{} against

\subsection{One driver, three runtimes}\label{sec:runtimes}
Docker accepts alternative OCI runtimes per container, and the driver passes
one through as a single field (\texttt{BOXED\_DOCKER\_RUNTIME}). Nothing
else changes: the same control plane, agent, image, and harness ran under
\texttt{runc}, under gVisor's \texttt{runsc} (a user-space kernel), and
under Kata Containers (a QEMU microVM with its own guest kernel) on one GCE
\texttt{n2-standard-4} with nested virtualization. This is the runtime-level
version of the backend switch the interface was designed for.
Table~\ref{tab:runtimes} gives the result; Kata's campaign was cut to
$2\times40$ lifecycles and one short sweep because each lifecycle boots a
virtual machine.

Boxed's lifecycle is \RuncBoxedMedian{} under \texttt{runc},
\RunscBoxedMedian{} under gVisor (\RunscVsRuncBoxed), and
\KataBoxedMedian{} under Kata (\KataVsRuncBoxed). The substrate cost is
\RuncOverhead{}, \RunscOverhead{}, and \KataOverhead{}: close to a
constant, so it is \RuncCostShare{} of a container lifecycle,
\RunscCostShare{} of a gVisor one, and \KataCostShare{} of a microVM one. The boundary sets the price; the control
plane and agent do not. Kata's raw stock lifecycle is \KataKnobStock{} on this host and its
hardened one \KataHardMedian{}; isolating the flags (\texttt{knobs.csv},
three runs each), network \texttt{none} takes a bare Kata boot from
\KataKnobStock{} to \KataKnobNetNone{} and the one-core CPU quota to
\KataKnobCpusOne{}, because the quota throttles QEMU while the guest
boots. Two settings free under \texttt{runc}, where network \texttt{none}
is faster than the bridge, cost seconds under a microVM. So the driver
gained two settings: an operator-created Docker network that the driver
verifies is \emph{internal} with inter-container traffic disabled, used
instead of \texttt{none}, and a switch that drops the CPU quota while
keeping the memory and PID limits. The last two rows of
Table~\ref{tab:runtimes} measure them: under Kata the Boxed lifecycle
falls from \KataBoxedMedian{} to \KataAwareBoxedMedian{}
(\KataAwareVsRuncBoxed{} \texttt{runc}) with \KataAwareDenied{} of 12
still denied, both egress vectors included. Throughput follows the same
order (\RuncPeak{}, \RunscPeak{}, \KataPeak{} sandboxes/s,
\KataAwarePeak{} with the settings); Kata also failed to create
\KataTPErrors{} of \KataTPTotal{} sandboxes once concurrency reached
\KataTPFirstErrConc{}, where the other runtimes had none.

The escape probe under the three runtimes is the more instructive result.
All twelve vectors are denied under \texttt{runc} and gVisor, and eleven
under Kata, identical across three runs. Three of the verdicts depend on
the probe reading the host rather than the sandbox, because a runtime with
its own kernel changes what an attempt looks like from inside. Under gVisor
and Kata, \texttt{unshare} succeeds, but the new namespace's inode is
absent from the host's \texttt{/proc}: it lives inside the sandbox's
kernel, and the probe scores it by that host check. Under both, the fork storm and the memory bomb kill the whole
sandbox, agent included, where under \texttt{runc} only the offending
process dies. Kata's guest kernel has no module loading at all
(\texttt{init\_module} returns \texttt{ENOSYS}).

The one undenied vector is \texttt{PTRACE\_ATTACH} on the agent under
Kata. Under \texttt{runc} that attach was denied by the host kernel's Yama
scope; Kata's guest kernel has no Yama, the workload and the agent both run
as root, and a same-uid attach needs no capability, so the attach succeeds.
The denial in Section~\ref{sec:escape} was the host's policy, not Boxed's,
and the stronger boundary removed it. The fix is one line: the agent now calls
\texttt{prctl(PR\_SET\_DUMPABLE, 0)} at startup, after which the kernel's
own access check refuses a tracer without \texttt{CAP\_SYS\_PTRACE},
which the driver drops. Re-running the probe with that agent on the same
host type gives \KataDeniedFixed{} of 12 under Kata
(\KataFixedRuns{} runs, \KataFixedConsistent), with the attach failing
\texttt{\KataPtraceFixedEvidence}, and \RuncDeniedFixed{} and
\RunscDeniedFixed{} of 12 under \texttt{runc} and gVisor. The lifecycle numbers in this section predate that change; a
\texttt{prctl} at startup is off the lifecycle path and was not
re-measured.

\subsection{A deployed competitor on the same host}\label{sec:openhands}
OpenHands~\cite{openhands} is the closest design sibling in
Section~\ref{sec:related} and its agent-server sandbox is self-hostable, so
the harness was pointed at it on the same host type: the container is
started exactly as the OpenHands SDK's \texttt{DockerWorkspace} starts it,
the harness waits for its health endpoint, and commands go through its bash
API (Table~\ref{tab:openhands}). The lifecycle is \OHMedian{}

creates one sandbox per session and runs many actions in it, so that cost
is paid per session where Boxed pays per task. The twelve vectors matter

no PID limit (\OHEvForkBomb), no memory limit, and a bridge network from

hostname and a service-account access token from inside the sandbox. The
unprivileged user also has passwordless \texttt{sudo}. These are the SDK's defaults; OpenHands documents custom sandbox images
for operators who need more.

The laptop plateau in Section~\ref{sec:throughput} could be the four
cores or the one Docker daemon. To tell them apart, the throughput sweep was repeated ten

\subsection{Threats to validity}
The laptop measurements ran inside a virtual machine on a machine in use;
the native Linux campaign removes both conditions and reproduces the
relative results, so the comparison the paper rests on, Boxed against raw
Docker with host, image, and command fixed, holds on both. Absolute
latencies do not transfer between hosts. Each repeat ran the three configurations in a fixed order. The
Kata numbers come from nested virtualization, which inflates a microVM
boot; the runtime ordering and knob attribution survive that, the absolute
Kata latency does not, and Kata's $n$ is 80 and 200. OpenHands was measured
in its SDK's default configuration; a deployment that follows its
custom-sandbox guidance would score differently, and its per-session
lifecycle is not the per-task one Boxed pays. The escape probe
is twelve vectors on one image, and it tests configuration; it does not test
kernel vulnerabilities.
Throughput lifecycles are create$\rightarrow$destroy without an exec, so they
measure the daemon's container churn rate and not the latency an agent
sees. The figures for other systems in Table~\ref{tab:compare} are vendor
claims we did not reproduce. The agent trace uses one model and twenty tasks,
three times, on a loaded host.

\section{Discussion}\label{sec:disc}

\subsection{What the runtime swap says about the design}
Section~\ref{sec:runtimes} is the closest this paper comes to testing the
interface claim. The control plane and agent did not change and did not
need to; a one-field change moved the substrate from a shared kernel to a
user-space kernel to a guest kernel, and its own cost stayed flat. Two
things did change. The hardening had been tuned against \texttt{runc}, and
two of its settings were expensive under Kata until the driver gained the
internal network and the quota switch (\KataAwareSpeedup{} on the
lifecycle, nothing given up on the probe). And the agent's placement as a
peer process, flagged in Section~\ref{sec:impl}, became a real
\texttt{ptrace} exposure once the host kernel's Yama policy was no longer
underneath it; the stronger boundary did not create that gap, it removed
the policy that had been masking it.

\subsection{Pool-based sandbox reuse}
The driver creates a fresh container per request, which guarantees a clean
start and pays the create phase every time; create is the largest phase in
Table~\ref{tab:lifecycle} and nearly all of a microVM lifecycle. Reusing a
warmed sandbox for compatible follow-up requests would spread that cost, as
Oakes \emph{et al.}'s SOCK~\cite{sock} does with an LRU cache of paused
containers, and the interface already lets \texttt{Create} return an
existing identifier; what reuse costs in isolation has to be measured
first.

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\section{Future Work}\label{sec:future}

The limitations above set the order of work: applying the microVM
settings automatically when the driver detects a microVM runtime, instead
of by operator flag; a custom seccomp profile and an egress policy, so the network
restriction is Boxed's and not the host's; sandbox reuse, measured for the
latency it saves and the isolation it weakens; a Firecracker driver, which
the runtime swap does not reach because Firecracker under Docker needs
block-device rootfs storage; then a multi-host scheduler, since
Section~\ref{sec:scaling} shows one daemon is the ceiling, and a Wasm/WASI
backend once the toolchain runs unmodified language runtimes.

\section{Conclusion}\label{sec:conc}

Boxed is a Docker-based execution substrate for LLM agents that create, use,
and destroy sandboxes many times per task: a streaming in-sandbox agent, a
one-round-trip create, and a self-hosted control plane behind an interface
meant to admit stronger backends. The substrate costs \BoxedOverheadPct{}
of a raw Docker lifecycle on a laptop and on an idle server alike, and the
hardening it applies makes raw Docker faster than stock defaults on both.
The same driver ran under \texttt{runc}, gVisor, and a Kata microVM with
its cost flat across the three, the backend switch the interface was built
for; the swap exposed a \texttt{ptrace} attach on the agent that
only the host kernel's policy had been stopping, since closed in the agent
and re-verified under Kata, and two hardening settings that cost seconds
under a microVM until the driver learned to replace them. Against the
OpenHands sandbox on the same host, Boxed is \OHVsBoxed{} faster per
lifecycle and denies three vectors that OpenHands' defaults do not, one of
them the cloud metadata endpoint. Scored by post-conditions read from the host, the hardened driver stops
\BoxedEscapeDenied{} of \BoxedEscapeTotal{} escape vectors under
\texttt{runc}; signature matching would have reported
\BoxedEscapeSigDisagree{} of them as failures. Open items are in
Sections~\ref{sec:disc} and~\ref{sec:future}. Implementation, harness, campaign runner, and all
raw traces are MIT-licensed at
\url{https://github.com/akshayaggarwal99/boxed} (tag
\texttt{\BoxedReleaseTag}); \texttt{make tables} regenerates every
number, table, and figure here.
